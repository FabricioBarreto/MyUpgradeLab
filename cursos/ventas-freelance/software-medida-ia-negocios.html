01 · Introducción

Hay una diferencia enorme entre "sé programar" y "tengo un negocio que ayuda a otros negocios a funcionar mejor". Este curso es sobre cruzar esa linea.

Esta guia conecta dos habilidades que ya trabajamos por separado en UpgradeLab: construir con IA (la serie Programar con IA) y vender de forma consultiva (Venta Consultiva). Aca las juntamos en un solo caso, de principio a fin: vas a ver como se identifica el problema real de un negocio, como se construye una solucion de software a medida usando herramientas de IA gratuitas, y como se la vende con una discovery call — sin necesitar ser un programador experimentado ni un vendedor nato.

El hilo conductor es un caso concreto: un taller mecanico. Vamos a mapear sus problemas reales (que trabajos priorizar, como armar y mandar presupuestos, como recordarle a los clientes el proximo service) y construir una solucion real para eso. El metodo se repite igual para cualquier otro rubro — al final vas a poder aplicarlo a peluquerias, estudios contables, gimnasios, o el negocio que se te cruce.

Qué vas a poder hacer al terminar esta guía Elegir un nicho de negocio concreto para especializarte, mapear sus problemas reales en una conversacion, construir una solucion funcional con herramientas de IA gratuitas, mostrarla en una discovery call conectando con el framework SPIN, y definir como cobrar por ese trabajo.

02 · Elegir un nicho de negocio local

"Le hago software a cualquiera" es mucho mas dificil de vender que "me especializo en resolver esto para talleres mecanicos".

Elegir un nicho especifico tiene ventajas concretas:

  • Podes reusar la solucion. Una vez que armaste el sistema para un taller, adaptarlo para el siguiente taller es mucho mas rapido que empezar de cero.
  • Hablas el idioma del cliente. Si entendes como funciona un taller, la discovery call fluye distinto — ya sabes que preguntar.
  • Te referencian dentro del mismo rubro. Un dueño de taller conoce a otros dueños de taller — el boca en boca funciona mejor dentro de un nicho que de forma generica.
Como elegir tu nicho Pensa en negocios locales que conozcas de cerca (por un familiar, un conocido, un lugar que frecuentas) — tener un punto de entrada real hace mucho mas facil conseguir la primera conversacion.

03 · El caso: taller mecánico — mapeando el problema real

Antes de construir cualquier cosa, hay que entender que le pasa al negocio en el dia a dia. Esto es exactamente lo que ya vimos en Venta Consultiva: diagnosticar antes de ofrecer.

Conversando con el dueño de un taller mecanico tipico, aparecen problemas como estos:

Problema realComo se manifiesta
Orden de prioridad de trabajos No hay un sistema claro para saber que auto atender primero cuando hay varios esperando
Presupuestos Se arman a mano o de memoria, se demoran en mandarse, y a veces se pierden en WhatsApp
Recordatorio de service Nadie le avisa al cliente cuando le toca el proximo mantenimiento — se pierden clientes recurrentes por eso
Preguntas de diagnostico (aplicando SPIN, ver Venta Consultiva)Situacion: ¿Como manejan hoy el orden de los autos que entran al taller? Problema: ¿Que es lo que mas les hace perder tiempo de esa forma de trabajar? Implicacion: Si esto sigue igual, ¿cuantos clientes creen que se pierden por no hacer seguimiento de sus services? Necesidad-beneficio: Si esto se resolviera, ¿que cambiaria en el dia a dia del taller?

Con estas respuestas ya tenes el mapa completo de lo que hay que construir — no antes.

04 · Construir la solución con herramientas de IA gratuitas

Con el problema mapeado, construir se vuelve mucho mas simple — vas a usar las mismas herramientas de la serie Programar con IA Nivel 1 (Bolt.new, Lovable, v0), aplicadas a este caso puntual.

1

Definí las tres funciones minimas

Basado en el diagnostico del capitulo anterior: una lista de trabajos con prioridad, un generador de presupuestos, y un sistema de recordatorios. Nada mas por ahora.

2

Construí con un prompt basado en el diagnostico real

Usa las respuestas concretas del cliente, no una descripcion generica.

3

Iterá viendo el resultado

Igual que en Programar con IA Nivel 1: mira lo que se genero antes de pedir el siguiente cambio.

Prompt inicial de ejemplo para este casoQuiero un sistema simple para un taller mecanico. Tiene que permitir: cargar autos que entran con una prioridad (urgente, normal, puede esperar), armar un presupuesto por auto con lista de items y monto total, y marcar la fecha del proximo service para mandar un recordatorio. Estilo simple, pensado para que lo use el dueño del taller sin ayuda tecnica.
Ojo: el objetivo de esta primera version no es venderla terminada — es tener algo funcional para mostrar en la discovery call. El alcance final se define despues, con el cliente ya interesado (ver capitulo 5).

05 · De la demo al cliente: la discovery call

Ahora entra en juego todo lo que ya viste en Venta Consultiva — mostrar una demo funcionando cambia por completo la conversacion.

La diferencia entre vender una idea y vender algo que ya existe es enorme. En vez de describir lo que harias, le mostras al cliente una pantalla funcionando con datos parecidos a los suyos. Eso reduce la objecion mas comun ("no se si esto realmente me sirve") antes de que aparezca.

Guion para presentar la demoTe arme algo basado en lo que charlamos la vez pasada: [mostrar pantalla]. Esto resuelve puntualmente el tema de [problema/implicacion que el cliente menciono]. Todavia es una primera version — quiero que me digas que le cambiarias antes de dejarla lista del todo.

Notá que la ultima frase invita al cliente a involucrarse en el ajuste final, lo cual lo acerca mucho mas a decir que si — ya se siente parte de la solucion, no solo alguien que la va a comprar.

06 · Cómo cobrarlo

Hay dos modelos principales, y cada uno tiene sentido segun el caso.

ModeloCuándo tiene sentido
Pago único El cliente quiere ser dueño de la solucion y no espera cambios frecuentes despues de la entrega
Mensualidad por mantenimiento Incluye ajustes, soporte, y mejoras continuas — genera ingresos recurrentes en vez de un pago unico
Recomendación Para negocios locales chicos, un modelo mixto suele funcionar bien: un pago inicial por la version funcional, mas una mensualidad chica por mantenimiento y soporte. Esto te da ingresos recurrentes sin depender de conseguir un cliente nuevo cada mes.

07 · Replicar el método en otros rubros

El proceso completo — diagnosticar, construir minimo viable, mostrar demo, vender, cobrar recurrente — se repite igual en cualquier negocio local.

RubroProblema típico a resolver
Peluquerías / barberíasSistema de turnos con recordatorio automatico
GimnasiosSeguimiento de vencimiento de cuotas y asistencia
Estudios contablesSeguimiento de vencimientos impositivos por cliente
Kioscos / almacenesControl simple de stock y productos por vencer

En todos los casos el metodo es el mismo: primero la conversacion de diagnostico, despues la construccion minima, despues la demo, despues la venta.

08 · Checklist y próximos pasos

  • Elegiste un nicho de negocio local especifico para especializarte.
  • Mapeaste el problema real de un negocio con preguntas de diagnostico, no asumiendo la solucion.
  • Construiste una version funcional minima con herramientas de IA gratuitas.
  • Mostraste la demo en una conversacion real, conectando con el framework de Venta Consultiva.
  • Definiste como vas a cobrar: pago unico, mensualidad, o un modelo mixto.
